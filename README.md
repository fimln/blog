# fimln Blog

Jekyll with a locally vendored no-style-please theme, permanent dark bluish
colors and self-hosted Fira Sans. Articles keep their existing URLs under `/blog/`.

## Run locally

Install Ruby from `.ruby-version` and Bundler from `Gemfile.lock`.
On Windows, use a WSL Debian terminal. From the repository root:

```bash
export PATH="$(ruby -r rubygems -e 'print Gem.user_dir')/bin:$PATH"
export BUNDLE_PATH="$HOME/.bundle/blog"
bundle install
bundle exec jekyll serve --host 127.0.0.1 --port 4000 --force_polling
```

Open http://localhost:4000/blog/ and stop with Ctrl+C.
Refresh after edits; restart after changing `_config.yml`.
Use `--port 4001` if port 4000 is occupied.

## Edit the blog

- Posts: `_posts/YYYY-MM-DD-title.md`, with `layout: post`.
- Optional article image: `image: /assets/images/example.jpg`. Covers are
  sized as 1200x400 before loading; for another size, use `image:` with
  `path`, `width` and `height`.
- Optional article language: `lang: id` (the site default is `en`).
- Colors, typography and breakpoints: `assets/css/main.scss`.
- Templates: `_layouts/` and `_includes/`.
- Search: `/search/`, with a full-text index generated by `search.json` and local
  `assets/js/search.js`. The index loads only after a query of at least two
  characters. Search is case-insensitive, matches all query words, prioritizes
  titles/topics and shows up to ten results. There is no fuzzy matching.
- Metadata, menu, pagination and URL structure: `_config.yml`.
- Local Fira Sans Regular/Bold/Italic WOFF2: `assets/fonts/`, with its license.
- Theme provenance and MIT license: `vendor/no-style-please/`.

All runtime assets are local, including article icons and dated GitHub stats
snapshots. External links remain references. Build tools still require Ruby and
the gems locked in `Gemfile.lock`; Ruby is pinned in `.ruby-version`.

See `DEPENDENCIES.md` for versions, licenses and upstream maintenance. Run
`.\package.ps1` from the repo root for
the self-contained production ZIP at `dist/blog-static.zip`.

For Kiro, open this repository as the workspace. The three files in
`.kiro/steering/` provide always-included product, stack and workflow guidance.
No hooks, MCP servers or AI-DLC integration are required for this blog.

Production build (from WSL):

```bash
JEKYLL_ENV=production bundle exec jekyll build
```

## Publish

Push to `master` to build and deploy through `.github/workflows/pages.yml`.
GitHub Pages uses the GitHub Actions publishing source. Ruby and gems follow
the committed version files; actions are pinned to commit hashes.
Only the generated `_site` artifact is published. `gh-pages` is a legacy output
branch and is no longer used for deployment; do not merge source into it.
The workflow can also be run manually from the repository's Actions tab.

The local, untracked `deploy.ps1`/`deploy.sh` helpers commit only `_posts` and
`assets/images`, then push `master`. Commit layout, style, config or search
changes separately.
